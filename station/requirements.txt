# **No runtime dependencies at all**, for a station with no receiver fitted.
#
# Everything the agent needs is in the standard library on purpose: an
# unattended box in the field should boot with what is in its image and never
# need to install anything.
#
#   python -m venv .venv && .venv/bin/pip install -r requirements.txt
#
# `redis>=5.0` used to be the one entry here and went with the Redis transport.
# Contract 2.0 defines a single transport — one authenticated WebSocket to the
# platform's /broker — and the station writes that client out itself, for the
# same reason it writes out the SDR driver: a protocol this small is less to
# carry than a library that speaks it.

# Optional, and only for a station with a real RTL-SDR airband receiver fitted.
# Deliberately NOT installed by default — uncomment, or:
#
#   .venv/bin/pip install numpy
#
# numpy>=1.24
#
# Why it is optional rather than a dependency
#
# The receiver has to mix, filter and decimate 240 000 complex samples a second.
# That is around six million multiply-accumulates per second in the cheapest
# arrangement that works (gsu/radio/am.py explains the arithmetic), and CPython
# is one to two orders of magnitude short of it. There is no version of this
# that runs in pure Python, so the choice is numpy or no hardware receiver —
# not numpy or a slower receiver.
#
# The cost, honestly
#
# On amd64 and arm64 PyPI publishes manylinux wheels and `pip install numpy`
# takes seconds. 32-bit arm (armv7) has no PyPI wheel, so the Docker image pulls
# one from piwheels instead (deploy/Dockerfile), which links the system OpenBLAS
# the image then installs — still a prebuilt wheel, no compiling on the box. A
# from-source build on a 32-bit Pi is minutes and can run it out of memory,
# which is exactly why the image does not do it.
#
# Why that does not spoil the property this file exists to protect
#
# The station still boots, enrols, senses and publishes with nothing installed.
# numpy is imported lazily and only by the RTL-SDR driver; a box without it
# reports "numpy is not installed" against the radio slot and carries on,
# exactly as a box with no dongle plugged in does. So the no-dependency
# guarantee holds for every station that has not been fitted with a receiver,
# and the cost is paid only where the capability is wanted.
#
# scipy is NOT needed and should not be added. Remote-Radio's DSP used
# `scipy.signal.firwin` and `lfilter`; both are reimplemented in
# gsu/radio/am.py, which is some thirty lines against a large compiled
# dependency.
#
# The RTL-SDR driver also needs the librtlsdr shared library, and the Opus
# encoder needs libopus — neither is a pip package. Both are installed in
# deploy/Dockerfile, which is where they belong: installing them on the *host*
# makes the radio work from a shell on that box and not at all from the agent,
# because the host's packages are invisible inside the container.
