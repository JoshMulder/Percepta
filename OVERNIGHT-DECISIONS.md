---

## 1. TLS everywhere, with a private CA the station pins — **REVIEW**

**Decision.** Both the broker and the API now serve TLS from a private CA
generated by `server/scripts/make_certs.sh`. Stations receive `broker.ca_pem` at
enrolment and verify against that CA alone.

**Why not Let's Encrypt.** A station is unattended kit that should trust exactly
one issuer — ours — rather than every public CA on earth. Public PKI is the
right answer for the browser console on a real domain; it is the wrong answer
for machine-to-machine between a fixed pair of endpoints. This is also precisely
what `contract/enrolment.md` §4 already specified and I had left unimplemented.

**What it costs you.** Your browser shows a certificate warning on
`https://192.168.2.49:8000` until you trust the CA locally. That is expected. It
does **not** affect stations.

**Reverse if** you put the console on a public domain, in which case it wants a
real certificate while stations keep pinning the private CA.

## 2. The plaintext listeners are gone, not merely discouraged — **REVIEW**

**Decision.** Redis runs with `--port 0`, disabling the unencrypted listener
outright. The API serves only HTTPS.

**Why.** A station misconfigured to `redis://` or `http://` would otherwise send
its enrolment token and receive its credential in clear, **and appear to work
perfectly**. A silent downgrade is worse than a hard failure because nobody finds
out. There is now no way to reach either service unencrypted.

**Consequence.** Anything of yours pointing at `http://192.168.2.49:8000` will
stop working and needs `https://`.

## 3. The broker requires a password; `default` is closed

`REDIS_PASSWORD` is set in `server/.env` and `requirepass` is enabled. This was
the last gap between the isolation model as documented and as enforced: per-
station ACL principals bound whoever used them and nobody who did not.

## 4. Station broker principals are rebuilt from the database — **REVIEW**

**Decision.** Redis holds ACL users in memory only, so a broker restart used to
lock out every station. The platform now rebuilds each principal at start-up
from `station_credentials.secret_hash`.

**Why this is safe.** Redis accepts an already-SHA-256-hashed password (`#<hex>`),
and that column is exactly that hash. So the platform reconstructs the precise
set of passwords a station should accept **without ever holding a plaintext
secret**. It also made revocation exact: the set is recomputed from what is
currently valid rather than patched.

## 5. Backups exist but are not scheduled — **REVIEW**

`server/scripts/backup.sh` works and the restore has been rehearsed into a
scratch database (5 stations, 5 users, 98 credentials recovered intact). See
`server/docs/06-backup-and-restore.md`.

**I did not add a cron job**, because where backups should live is your call and
putting them on the same disk as the database — which is all I can do from here —
protects against a bad migration and nothing else. This is the largest remaining
gap in the list and it needs a destination, not more code.

## 6. The Pi gets a systemd service, not a container image — **REVIEW**

You said "image". I judged Docker wrong for a Pi 2B: 1GB RAM, ARMv7, and a
single USB 2.0 host shared with Ethernet, against a pure-Python agent whose only
dependency is `redis`. A systemd unit starts faster, survives reboots more
simply, and leaves the USB bus and memory to the sensors.

Easy to reverse — the agent is plain Python — but I would want a reason.

## 9. Two bugs worth knowing about, both found by testing rather than reading

**redis-py lets the URL override your keyword arguments.**
`ConnectionPool.from_url` ends with `kwargs.update(url_options)`. Connecting
with `Redis.from_url(url, username=..., password=...)` where `url` carries
credentials silently authenticates as whoever the URL names. It broke the
enrolment verifier the moment the platform URL gained a password, and it would
have broken the station in exactly the same way.

**A CA without `basicConstraints` and `keyUsage` is accepted by `redis-cli` and
refused by Python.** My first CA had neither; `redis-cli --cacert` was perfectly
happy and Python's `ssl` refused it. Testing TLS with `redis-cli` alone is not
evidence a Python client will connect. The CA was regenerated with both.

## 10. Decisions the station side took, which I checked rather than accepted

- **Enrolment refuses to run without a CA.** The CA arrives *at* enrolment, so
  there is a chicken-and-egg. Rather than trust-on-first-use, the CA is carried
  to the box out of band and its fingerprint verified by eye at install
  (`DEPLOYMENT.md` step 3). That is the stronger choice and the one step in the
  runbook a person must check. **REVIEW** — it does mean you carry `ca.crt` to
  the Pi on a stick or over scp before enrolling.
- **Serial port no longer defaults to `/dev/ttyUSB0`.** Two USB-UART adapters
  swap between boots, so each driver would read the other's traffic and both
  instruments would present as failed. It defaults to empty and the console
  offers detected `by-id` names. **This is why you must plug both adapters in
  before configuring, not after.**
- **Baud is per-device now**, with 57600 for the ping RX Pro. Everything
  previously got 4800, which for the ping RX would have read as a dead receiver.
- **Raspberry Pi OS Bookworm, not Bullseye.** The code needs Python 3.11 for
  `datetime.UTC`. The installer checks and refuses with that explanation.
  **REVIEW** — confirm your SD image before you travel to the site.
- **GPS deliberately not implemented in Python.** It belongs in chrony via
  gpsd/PPS, so the receiver you intend to fit becomes a config file rather than
  a code change, and the station starts reporting `disciplined by gps` on its
  own. chrony is installed for that reason rather than timesyncd.

What I verified myself, on this machine, rather than taking on report: the
station enrols over HTTPS against the real CA, publishes over `rediss://`, and
**passes full contract conformance with the CA pinned and no `--insecure`**.
Pointed at a plaintext broker it refuses before opening a socket, raises a
critical `uplink.refused`, records an event, and keeps sensing locally. Its 109
tests pass.
